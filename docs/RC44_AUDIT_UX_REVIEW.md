# RC.44 — שיפור קריאות יומן המערכת

## התקנה
העתיקו את שלושת קובצי `src/` מתוך הפאץ' למיקומם המקורי בפרויקט. לא נדרשת הרצת SQL.

## מה השתנה
- תיאור פעולה ברור יותר עבור אירועי שיבוץ נבחרים.
- שמות שדות וערכים נפוצים בעברית.
- הצגת שדות ששונו בלבד כאשר קיימים old_values/new_values.
- הפרדה בין מידע אנושי לפרטים טכניים, כולל JSON מלא לפי דרישה.
- הבחנה בין 'מערכת' לבין 'מבצע לא ידוע' כשאין מזהה משתמש.

## מגבלות
- לא בוצעה המרת UUID לשם עובד/תפקיד, משום שמקור נתונים היסטורי אמין לא הוגדר.
- מיפוי השדות מבוסס על אירועים שנצפו וניתן להרחיבו בהמשך.
- בדיקת TypeScript/Build לא הושלמה בסביבת הבדיקה: תלויות node_modules לא הועתקו מטעמי יעילות. הריצו npm run build בפרויקט המקומי.
- אין שינוי למנגנון רישום אירועים במסד הנתונים.

## סקירת ניקוי פרויקט — ללא מחיקה אוטומטית
**קבצים שנראים זמניים/נגזרים, לאחר בדיקת תוכן ושימוש:**
- `gvk-local-schema-import.log`, `supabase-start-debug.txt`: לוגים מקומיים.
- `gvk-local-schema-test.sql`: snapshot/בדיקת סכימה; לשמור מחוץ לריפו אם נחוץ להשוואה.
- `respond_to_dynamic_shift_exchange_request.backup.sql`: גיבוי נקודתי, לשמור בארכיון לפני הסרה.
- `supabase/config.toml.backup`: גיבוי הגדרות; לבדוק אם נדרש.
- `supabase-audit/` ו-`supabase-audit.zip`: ייתכן שכפול של תוצרי ביקורת; לבדוק תוכן ותאריך.
- `project-tree.txt`: קובץ עץ פרויקט סטטי וגדול; אפשר לייצר מחדש.
- `tatus`: קובץ חריג בשם זה; לבדוק לפני מחיקה.
- `node_modules/`, `dist/`, `dev-dist/`: תוצרי התקנה/בנייה מקומיים, לא קוד מקור; מחיקה רק לצורך ניקוי מקומי ובנייה מחדש.

**לא למחוק ללא סקירה פרטנית:**
- `supabase/migrations/`, `supabase/functions/`, `src/`, `public/`, `docs/`, `tests/`, `scripts/`, `sql/OPTIONAL_rc44_*` (כולל rollback), `.git/`, `.env.local`.

**אבטחה:** ה-ZIP שנשלח כולל `.env.local` ו-`.git/`. להבא ליצור ZIP ללא קובצי סודות, node_modules, dist ו-.git. אם הסודות נחשפו מחוץ לערוץ מהימן, לשקול החלפת מפתחות.
